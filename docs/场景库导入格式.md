# 场景库导入格式（管理员）

后台「场景导入」支持：

| 文件 | 说明 |
|---|---|
| `.md` / `.txt` | 单个场景库或框架库文件 |
| `.zip` | 内含多个 md（可分目录），一次导入 |

**模式**

- `更新或新增（upsert）`：同名分类/场景/训练/框架 → 覆盖内容；没有的 → 插入。**不删除**库里多出来的条目。
- `仅新增（add_only）`：已存在则跳过。

匹配键：分类 `name`、场景 `category+title`、训练 `scenario+title`（仅公共场景）、框架 `code`。

---

## 场景库 Markdown

文件头建议写 `# talktool-catalog v1`。

```markdown
# talktool-catalog v1

# 分类：职场赋能

## 场景：跨部门协作
副标题：跨部门协作沟通更顺畅

### 训练：跨部门要资源，对方说排期满了

- 压力：中压
- 时长分钟：3
- 用户角色：市场部项目负责人
- AI角色：技术部张工，忙碌但对事不对人
- 训练目标：换位思考、需求价值、双赢方案
- 开场白：又是你们市场部？这个月排期早就满了。

#### 场景描述

（完整背景，展示给用户，含角色、情境、任务要求）

#### 常见误区

- 一上来就说老板定的必须做
- 跟对方争论谁更忙

#### 推荐框架

- need_formula｜张工，这个活动是本季度拉新主战场（共同目标）……
- listen_read_say｜先听出他的怨气，再谈这一次。
```

规则摘要：

- 标题前缀：`# 分类：` / `## 场景：` / `### 训练：`（也可用英文半角冒号）
- 压力只能是：`低压` / `中压` / `高压`
- `推荐框架` 一行一个：`框架code｜本场景示例说法`（框架须已在库中，或同次 ZIP 里先导入框架文件）
- 一个文件可含多个分类；ZIP 可拆成多个 md

## 表达框架 Markdown

文件头建议写 `# talktool-frameworks v1`。

```markdown
# talktool-frameworks v1

## 框架：PREP 观点表达法

- code：prep
- 分类：结构表达
- 摘要：先亮观点，再给理由和例子，最后回到观点。
- 适用：被问看法、会议发言、临时点名
- 来源：C

### 步骤

1. P｜观点 Point｜第一句就表态
2. R｜理由 Reason｜给 1-3 个理由
3. E｜案例 Example｜具体事例或数据
4. P｜重申观点 Point｜回扣开头

### 通用示例

我认为下季度应该先抓老客户复购。……

### 常见误区

- 铺垫太长，半天不进观点

### 小技巧

- 先说「我的观点是……」给自己定锚
```

框架分类建议使用现有九类之一：结构表达、即兴与当众、向上沟通、团队管理、情绪与关系、社交破冰、说服与谈判、求职面试、自媒体创作。

## ZIP 示例结构

```
pack.zip
  frameworks.md      # talktool-frameworks
  catalog/
    职场.md
    面试.md
```

发给大模型整理内容时，请直接使用同目录下的 `场景库导入-发给大模型的提示词.md`。
