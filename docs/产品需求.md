# AI 沟通训练工具 —— 产品开发需求与提示词

> 用途：把以下完整需求交给 AI 编程模型（如 Claude / GPT / Kimi 等），生成可运行的应用。
> 本文档由 9 张参考截图逆向解析而来，描述了产品的页面结构、交互流程、数据模型与 AI 能力要求。

---

## 一、产品概述

开发一款**「AI 语音沟通训练」应用**：用户选择一个沟通场景（如"临时点名发言""平息客户怒火"），与 AI 进行**纯语音**角色扮演对练；训练结束后，AI 根据对话内容生成评估报告；所有训练历史可回看。

一句话定位：**沟通技巧的"健身房"——用 AI 扮演对手角色，让用户在低压/高压场景中练习说话。**

形态建议：微信小程序（参考产品即小程序）或移动端 Web App。用VUE来做。

## 二、页面结构（共 6 个页面）

### P1 训练场景页（首页 Tab：场景）

- 顶部导航栏：返回键 + 标题「训练场景」
- **左侧竖向分类栏**（固定），分类包括：职场赋能、酒桌文化、求职面试、社交建联、亲密关系、冲突化解、共赢协商、当众表达（分类可配置，后台可增删）
  - 选中态：浅蓝背景 + 左侧蓝色竖条 + 蓝色文字
- 右侧内容区：
  - 分类标题 + 右上角灰色小字「共 N 个分类」
  - **场景卡片列表**（白色圆角卡片）：场景标题（粗体）、一句话简介（灰色）、左下「N 个场景」、右侧 chevron 箭头
  - 上下滑动浏览，左侧分类与右侧内容联动
- 底部 Tab Bar（4 个）：首页 / 场景（当前选中，蓝色高亮）/ 练习本 / 我的

### P2 场景列表页（点击场景卡片进入）

- 顶部：返回 + 标题「场景列表」
- 所属分类标签（蓝色小字）+ 场景大标题 + 简介
- 「场景列表」小节标题 + 右侧「共 N 个场景」
- **训练卡片**：左侧方形封面缩略图（真实场景照片风格）、标题（最多两行）、场景描述（两行截断，如"你是公司销售部的一名员工，正在参加季度项目复盘会，会议主题是'如何提升下一季度的…"）、标签胶囊（如「低压」「约 3 分钟」）
- 列表底部显示「已加载全部场景」

### P3 场景介绍页（点击训练卡片进入）

- 顶部大图（封面图，图上叠加半透明渐变 + 分类小字 + 场景大标题）
- 三个信息胶囊卡片横排：**压力等级**（低压/中压/高压）、**预计时长**（约 N 分钟）、**训练方式**（纯语音）
- 「场景描述」卡片：完整的角色扮演背景设定文本，包含：
  - 用户扮演的角色（如"你是公司销售部的一名员工"）
  - 情境背景（如"季度项目复盘会，主题是如何提升下一季度的客户转化率"）
  - 触发事件（如"领导突然点名：'小李，说说你的看法'"）
  - **训练任务要求**（如"请使用'即兴发言2步走''即兴演讲4大公式'快速整理思路，在1分钟内说出自己的观点和建议"）
- 底部固定大按钮：「开始训练」（蓝色，圆角）

### P4 语音训练中页（核心页面）

- **整页蓝色背景**（沉浸式）
- 顶部：场景标题（超长省略）+ 副标题「低压模式 · MM:SS」计时器 + 麦克风状态图标
- 中央：圆形麦克风动效按钮（带扩散波纹动画，表示监听/播放状态）
- 状态文案区：
  - AI 说话时：「AI 讲话中，请稍候」
  - 提示文案：「训练过程仅用语音表达，不提供文字输入」
  - **实时延迟显示**（如「51 ms」，展示语音链路往返延迟）
  - 轮次提示：「请等提示"可以说话"后再回答」
- 底部按钮：「结束训练」（半透明描边样式）
- **状态机**：AI讲话中 → 用户可以说话（监听中） → 用户讲话中（识别中） → AI思考中 → AI讲话中……循环，直到用户点「结束训练」

### P5 训练报告页

- 顶部：返回 + 标题「训练报告」
- 概要卡片：场景标题、压力标签（如「低压训练」）、用时（0 分 32 秒）、状态（已完成训练）、时间戳（yyyy-MM-dd HH:mm:ss）
- **评估结果区**：
  - 正常情况：AI 生成的评估报告（表达逻辑、语言组织、应变能力、情绪管理等维度的打分 + 文字点评 + 改进建议）
  - **异常情况 1（时长过短）**：图标 + 「时长过短」+「本次对话时长过短，无法生成报告，可重新练习生成。」
  - **异常情况 2（主动放弃）**：标记为「主动放弃」，不生成报告
- 底部按钮：「返回训练记录」
- 底部免责声明（灰色小字）：「本次结果仅反映这一次训练中的表现。」

### P6 训练记录页

- 顶部：返回 + 标题「训练记录」
- 筛选胶囊：全部记录 / 本周 / 本月（选中为蓝色实心）
- **记录卡片列表**：场景标题（两行）、右上角状态徽章（已完成/时长过短/主动放弃，灰色或蓝色）、压力标签（低压）、时间戳 + 「训练 N 分 N 秒」、分隔线、报告摘要一行（如"本次对话时长过短，无法生成报告，可重新练习生成。"）、右侧蓝色链接「查看报告 >」
- 列表底部：「没有更多记录了」

## 三、核心功能流

```
浏览分类(P1) → 选场景(P2) → 看介绍(P3) → 点击"开始训练"
  → 语音对练(P4)：AI 扮演场景中的对手角色，与用户多轮语音对话
  → 点击"结束训练"
  → 生成报告(P5)：后端将整段对话文本交给 LLM 评估，生成结构化报告
  → 训练记录(P6)：按时间倒序展示，支持按周/月筛选，可回看报告
```

## 四、AI 能力要求（核心技术点）

### 1. 实时语音对话（P4）

- 方案 A（推荐，体验好）：**端到端实时语音 API**——如 OpenAI Realtime API、豆包·实时语音大模型、通义千问-Omni / Qwen3-Omni 实时通话，天然支持打断、低延迟（参考产品展示了 51ms 的链路延迟）
- 方案 B（成本低）：**三段式管道**——ASR（语音识别）→ LLM（对话生成）→ TTS（语音合成），需自行管理状态机与打断逻辑
- 必须支持：语音活动检测（VAD）、AI 说话时禁止用户输入（轮流对话）、对话全程计时
- **前端仅语音交互，不提供文字输入框**（这是产品设计硬约束）

### 2. 场景 System Prompt 模板

每个场景对应一段 AI 角色设定，模板结构：

```
你正在进行一场沟通训练角色扮演。
【场景背景】{场景描述全文}
【你的角色】{AI扮演的角色，如"你的直属领导王总"}
【用户角色】{用户扮演的角色}
【压力模式】{低压/中压/高压} —— 低压：态度友善、多鼓励引导；高压：态度强硬、追问施压、故意刁难
【训练目标】{该场景要考察的能力点}
【规则】开场由你先发言，用一句话把情境抛给用户；对话控制在{时长}分钟内；
全程口语化、简短，每次发言不超过3句话；不要跳出角色。
```

### 3. 训练报告生成

训练结束后，将对话全文 + 场景信息 + 评估维度交给 LLM，输出结构化 JSON：

```json
{
  "status": "completed | too_short | abandoned",
  "duration_sec": 192,
  "scores": {"逻辑表达": 8, "语言组织": 7, "应变能力": 6, "情绪管理": 8},
  "summary": "一句话总评",
  "highlights": ["做得好的点1", "点2"],
  "improvements": ["改进建议1", "建议2"],
  "detail_comment": "详细点评（Markdown）"
}
```

**边界规则**（从参考产品还原）：
- 对话时长过短（如 < 1 分钟）→ status=too_short，不生成报告，提示"可重新练习生成"
- 用户中途退出且无有效对话 → status=abandoned（主动放弃）

## 五、数据模型（建议）

```
Category  分类：id, name, sort_order
Scenario  场景大类：id, category_id, title, subtitle, sort_order
Drill     训练卡片：id, scenario_id, title, description(完整背景设定),
          cover_image, pressure_level(低/中/高), duration_min, mode(纯语音),
          ai_role, user_role, system_prompt, training_goal, status
Session   训练会话：id, user_id, drill_id, started_at, ended_at,
          duration_sec, status(completed/too_short/abandoned), transcript(对话全文)
Report    报告：id, session_id, scores(json), summary, highlights(json),
          improvements(json), detail_comment, created_at
```

## 六、UI 风格规格（还原参考设计）

- 主色：蓝色 `#3B9DF8` 系（按钮、选中态、训练中页面整页蓝色背景 `#4A9BE8` 左右）

- 标签胶囊：浅蓝底 `#E8F4FE` + 蓝字（如「低压」）
- 底部 Tab：选中蓝色、未选灰色，图标 + 文字
- 训练中大按钮：蓝色实心、全宽、圆角、底部吸底

## 七、技术栈建议（MVP）

- 前端：uni-app（一套代码同时出微信小程序 + H5）或 React Native / Taro
- 后端：FastAPI（Python）或 Node.js（NestJS）+ PostgreSQL / MySQL + Redis
- 语音：优先端到端实时语音 API（豆包实时语音 / OpenAI Realtime / Qwen-Omni），小程序端注意音频流方案（WebSocket + 音频帧）
- 对象存储：封面图、录音文件（可选留存）放 OSS / COS
- 用户体系：微信一键登录（小程序）或手机号验证码（H5）

## 八、MVP 范围（第一版只做这些）

1. P1~P4 四个页面 + 内置 8~10 个场景（覆盖 3~4 个分类即可）
2. 实时语音对练（含轮流对话状态机、计时、结束训练）
3. 报告生成（含 too_short / abandoned 两种边界处理）
4. 训练记录列表与报告回看（P5、P6）
5. 不做：支付、社交分享、排行榜、练习本（Tab 占位即可）
